# フリマキット

メルカリ・ラクマ・ヤフオク・PayPayフリマの画面に、

- **出品日時・更新日時の表示**（商品ページと検索結果の一覧、経過日数つき）
- **いいね数・コメント数の表示と、再出品候補の抽出**（「いいね1以下 かつ コメント1以下」などの条件で一覧）
- **定型文の挿入**（選んだ入力欄へ差し込み。`{商品名}` などの差し込み変数つき）
- **他サイトの横断検索**（売り切れ・落札済み検索を含む）
- **商品名・説明文・URLのコピー**

を足す Chrome 拡張です。ビルド工程はなく、`npm install` も要りません。

**出品・値下げ・再出品・コメント送信を自動で行う機能はありません。** 各社の規約は自動操作を禁じており、
まとめて取り下げ・再出品を繰り返すアカウントは利用制限の対象になります。
この拡張は、ページにすでにある情報を読みやすく出すことと、文章を入力欄に差し込むところまでを行い、
**押すのは常に人**です。これは方針の表明だけでなく、`tests/wiring.test.js` が
コンテンツスクリプト内の `.click()` `.submit()` `fetch()` を検査して落とすようにしてあります。

## 入れかた

1. Chrome で `chrome://extensions` を開く
2. 右上の「デベロッパーモード」をオンにする
3. 「パッケージ化されていない拡張機能を読み込む」を押し、このフォルダを選ぶ
4. メルカリなどを開くと、画面の右端に「フリマキット」のつまみが出ます

## 使いかた

画面右端のつまみを押すとパネルが開きます。

- **定型文**: 先にコメント欄などをクリックしてから定型文を押すと、その位置に差し込まれます。
  入力欄を選んでいない場合はクリップボードにコピーされるので、操作が空振りしません。
- **反応と再出品候補**: 一覧ページを開くと、条件に当てはまる商品が古い順に並びます。
- **他サイトで探す**: 検索ページならその言葉、商品ページなら商品名が最初から入ります。
- **設定**: ツールバーのアイコン →「設定」から、定型文の編集や機能の切り替えができます。

## 反応の薄い商品を見つけて、出し直す

「いいねもコメントも付いていない商品を探して、出し直して、告知を書く」までの手順です。
探すところと文章を用意するところを拡張が受け持ち、取り下げ・再出品・コメント送信は人が行います。

1. **探す。** メルカリの「出品した商品」を開き、パネルの「反応と再出品候補」を見ます。
   **いいね1以下・コメント1以下**が初期値で、設定画面の「再出品の目安」から変えられます
   （`0` にすると反応ゼロの商品だけが並びます）。並び順は出品から日数が経っている順です。
   一覧のカードにも `いいね0・コメント0（低反応）` と出るので、画面の側でも見分けられます。
   「一覧をコピー」で、商品名・反応数・経過日数・URL をタブ区切りで持ち出せます。
2. **写す。** 候補の商品ページを開き、パネルの「コピー」→「まとめて」で商品名・説明文・URLを取ります。
3. **出し直す。** 商品を削除し、出品画面へ写します。ここは拡張が触りません。
4. **告知を書く。** コメント欄（または説明文）をクリックしてから、定型文の
   **「出張セール告知」**を押すと、その場に差し込まれます。内容を確認して、送信ボタンは自分で押してください。

定型文の本文と発送日は、設定画面の「定型文」から編集できます。出張の日程が変わったらここを直します。
戻ったときに使う「出張から戻った」も同じ分類に入れてあります。

### なぜ自動でやらないか

この一連を自動化するには、拡張が商品ページを順に開いて削除と再出品のボタンを押し、
コメントを送信することになります。各社の規約が禁じている自動操作そのもので、
実際に止められるのは出品ではなくアカウントのほうです。取り下げと再出品の繰り返しも
検索順位の操作とみなされます。**手で押す限り正当な操作**なので、手で押せる形にしてあります。

## 「エラーが出て使いづらい」への作りの答え

この種の拡張が壊れるのは、ほぼ全部フリマ側の画面変更が原因です。以下はその前提で組んでいます。

| 壊れがちな作り | この拡張の作り |
| --- | --- |
| `props.pageProps.item.created` のような固定パスで値を取る | 埋め込みデータの木を歩いて、**商品IDが一致するノード**を探す。階層が変わっても追随する |
| CSSクラス名でボタンの挿し込み先を探す | 操作の入口は画面端の**固定パネル**。挿し込み先が消えても機能が消えない |
| どれか1つの機能が例外を投げると全部止まる | 全機能を `safe()` で囲み、**失敗した機能だけ**を止める |
| 値が取れないと無言で消える | 「取得できませんでした」と出し、**どの機能が失敗したか**をアイコンのポップアップに表示する |
| 取れた値をそのまま表示する | 秒/ミリ秒/ISO を正規化し、**ありえない日時は表示しない**（誤った日時を出すより出さない） |
| 関連商品の日時を拾って表示してしまう | 商品IDが一致しない場合は**表示しない**。取り違えを黙って起こさない |
| `el.value = ...` で入力欄に文字を入れる | React の内部状態が更新されず送信時に消えるため、**プロトタイプの setter + input イベント**で入れる |
| 拡張のCSSがサイト側と混ざる | パネルは **Shadow DOM** に閉じる。ページへ挿すのはバッジ2種類だけ |
| 最初の1ページでしか効かない | SPA の画面遷移を監視し、**URLが変わるたび作り直す** |
| 保存された設定が壊れると起動しない | 設定は壊れている前提で読み、**項目単位で既定値へ寄せる** |

## 未確認のこと

**フリマ各社の実ページに対する動作確認は行えていません。** この環境から各サイトへアクセスしていないためです。
特に次の 3 点は、実際のページで確認してください。

1. **埋め込みデータから日時が取れるか。** 上記のとおり構造変化には強く作ってありますが、
   そもそもデータがページに埋め込まれていない場合は取得できません。
   アイコンのポップアップで「埋め込みデータ 0 件」と出る場合がこれにあたります。
2. **いいね数・コメント数が埋め込みデータに載っているか。** `numLikes` `num_likes` `likeCount`
   `favorite_count` などの揺れは吸収してありますが、載っていなければ取得できません。
   その場合はパネルに「取得できませんでした」と出ます。DOM の見た目から数字を拾う作りには
   していません。関係ない数字を反応数として表示するほうが害が大きいためです。
   片方だけ取れた場合は、取れたほうだけで判定し、その旨をパネルに出します。
3. **一覧ページでバッジを挿す位置。** 商品カードの隣に置いていますが、レイアウトによっては
   見え方の調整が要ります。消えた場合も監視で貼り直します。

1 と 3 は `src/content/page-data.js` と `src/content/features/timestamps.js`、
2 は `src/common/extract.js` の `LIKE_KEYS` / `COMMENT_KEYS` に実際のキー名を足せば対応できます。

## 開発

```bash
npm test     # 日時の正規化・データ抽出・反応数の判定・URL解析・設定の検証（57件）
npm run check  # 全ファイルの構文確認
```

テストは Node 標準の `node:test` のみを使い、依存パッケージはありません。

### 構成

```
manifest.json
src/common/     log(安全実行と診断) / format(日時) / extract(データ抽出) / sites(サイト定義) / storage(設定)
src/content/    ui(Shadow DOMのパネル) / page-data(ページ解析の共有キャッシュ) / features/ / boot(起動と遷移追随)
                features/ = timestamps(出品日時) / reactions(反応数と再出品候補) / templates(定型文) /
                            cross-search(横断検索) / copy-text(コピー)
src/options/    設定画面
src/popup/      動作状況の確認
```

### 対応サイトを増やす

`src/common/sites.js` の `SITES` に定義を 1 つ足します。ホスト名・商品IDの形・検索URLの組み立てだけで、
DOM の構造には触れません。`manifest.json` の `matches` にも同じドメインを追加してください。
