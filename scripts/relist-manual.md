# ルーティンが止まっているときの再出品（手動）

## 結論

**再出品はクラウドのセッション（iOS / claude.ai から開くもの）では実行できない。Mac の上でやる。**

ルーティン（`Mercari relist 0000/0600/1800` / `Mercari hide sold 1100` / `Yahoo relist 1500`）は
Mac 上のブリッジワーカーで動いていて、メルカリのログイン状態もブラウザも Mac 側にしかない。
背景は `scripts/routine-recovery.md`（ブランチ `claude/mercari-6pm-routine-start-7ax7yv`）と
`scripts/README.md`（ブランチ `claude/routine-session-disconnects-amwqkk`）に既に書かれている。
この文書は「ルーティンが止まっていると気づいてから、実際に出し直すまで」をまとめ直したもの。

## いまの状態（2026-09-15 18:03 JST にクラウド側から確認）

| 確認したこと | 結果 |
| --- | --- |
| 直近のブリッジ（Mac）セッションの作成 | **2026-09-09 00:07 JST が最後**。以後 6 日間、ルーティンのセッションが立っていない |
| 18:00 の `Mercari relist 1800` | 18:03 JST 時点で新しいセッション無し（実績では 18:05 頃に作成される） |
| `list_environments` | `anthropic_cloud` の「デフォルト」1 つだけ。Mac のブリッジ環境は見えず、クラウドから Mac 側のセッションを作れない |
| `list_triggers` | 空。ルーティンの定義は Mac ローカルにあり、クラウドからは読めない |
| 他セッションへの問い合わせ | 到達可能なセッション無し。`Mercari relist *` にも `午前6時のルーティーン結果` にも話しかけられない |
| `jp.mercari.com` への接続 | ネットワークポリシーで遮断（`EGRESS_BLOCKED`）。商品ページの閲覧すらできない |

つまり「ルーティンが動いていない」が先にあり、その分の再出品が溜まっている状態。

## 手順

### 1. Mac を起こし、Claude Code を開く

ブリッジワーカーが再接続すれば、以降のルーティンは通常どおり発火する。
発火の確認は、セッション一覧にその時刻の `bridge` セッションが新しく立つかどうかで見る
（00:07 / 06:08 / 11:01 / 15:04 / 18:05 JST 頃）。

### 2. 発火を待たずに出し直す

Mac 側の Claude Code（ルーティンと同じ環境）に商品 URL を渡して、いつもの手順で再出品する。
クラウド側のセッションからは代われない。

### 3. 手作業で出し直す場合（Mac の Chrome）

フリマキット拡張を入れておくと、次の 3 か所が手作業のままでも速くなる。

1. 商品ページを開き、パネルの **コピー → まとめて** で商品名・説明文・URL を控える
2. 相場を見るなら **他サイトで探す → メルカリ 売切** で同等品の売値を確認してから価格を決める
3. 元の出品を削除し、**出品する** から控えた内容を貼り直す（画像は取り直し／再アップロードが必要）

拡張は入力欄への差し込みまでで、出品ボタンは押さない。各社の規約が自動操作を禁じているため。

## 再発防止

`bash scripts/mac-keep-awake.sh`（ブランチ `claude/routine-session-disconnects-amwqkk`）で
`caffeinate -dims` を LaunchAgent として常駐させる。フタを閉じて運用するなら
`sudo pmset -c disablesleep 1` も併用する（排熱に注意）。

ルーティン定義そのものを「毎回新しいセッションで起動する」形に変えるには、
まず `bash scripts/find-claude-routines.sh` で定義の場所を特定する必要がある。
