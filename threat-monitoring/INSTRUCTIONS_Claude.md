# 日次 Threat Monitoring 調査指示書（Claude専用版）

対象: 日本国内に関連する公開情報 / 目的: 攻撃（テロ・ローンオフェンダー・無差別殺傷・要人襲撃・放火・爆破・車両突入 等）の予兆となる Threat Indicator の早期発見・整理。

## 0. Claudeの実行能力と制約（最初に必ず確認）

| 項目 | 内容 |
|---|---|
| 使えるもの | WebSearch（公開Web検索）、WebFetch（公開URL取得）、サブエージェントによる並列調査 |
| 使えないもの | X/Instagram/Facebook/TikTok等へのログイン、X検索API、リアルタイム全件検索、DM・非公開グループ、LINE/Discord等の私的チャット |
| 帰結 | 「X全体を網羅検索」は不可。検索エンジンに索引された公開ページ、報道、警察・自治体・施設の公式発表、公開アーカイブが中心。網羅性は限定的 |
| 義務 | 各回の報告冒頭に「今回の到達範囲と未到達範囲」を書く。見つからない＝脅威なし、とは書かない |
| 補完 | ユーザーが提供するURL・スクショ・ログ（ログイン済み環境での検索結果）を受け取り、分析することは可能。収集はユーザー側、評価はClaude側という分担を推奨 |

## 1. 絶対ルール

1. 私的通信（DM、クローズドチャット、非公開グループ）は調査しない。公開の投稿・公開サーバー・公開掲示板のみ。
2. 推測禁止: 本名・住所・勤務先・学校・家族・精神状態・国籍・宗教・政治的所属等。特定を試みない。晒し（ドキシング）に資する整理をしない。
3. 公開投稿上の行動・発言・関係性のみを扱う。「フォロー」「同じ思想」だけで関連人物としない。
4. 具体的脅威を示唆する情報を見つけても本人に接触・対峙しない。通報先（警察110／緊急でなければ警察相談 #9110、サイバー事案は都道府県警サイバー窓口、プラットフォーム通報機能）に回す前提で報告する。
5. 単語単独で判定しない（革命・粛清・打倒・天誅・突撃 等）。Target / Time / Location / Method / Preparation の組合せで評価。
6. 事実と分析を分離。危険度と情報確度を分離。真偽未確認なら「公開情報上、具体的脅威を示唆する情報が確認された」と書き、脅威の事実化はしない。
7. 同一情報は重複計上しない。前回との差分を最優先。

## 2. 二段階方式

- Detection（広く）: 表記ゆれ・隠語・他言語を含めて検索。
- Assessment（厳しく）: 下記の指標の組合せのみで格付け。

## 3. 検索語設計

### 3-1 基本語
殺害予告 / 殺す / 爆破 / 放火 / 無差別 / 襲撃 / 刺す / 撃つ / 車で突っ込む / 道連れ / 見せしめ / 最後の仕事 / 全部終わらせる / 一矢報いる / 落とし前 / 天誅 / 討ち入り / 決起

### 3-2 表記変形（機械的に生成して検索）
- 伏せ字: 殺○ 殺◯ こ○す こ.す こ_す し○ね
- 分割: 殺 す / 殺・す / こ ろ す / こ｜ろ｜す
- ローマ字・英語: korosu / kill / bomb / shoot / stab / arson / attack / revenge / massacre
- 当て字・誤字・全角半角・小文字・カタカナ化・Unicode類似文字・絵文字（🔪💣🔥🔫）
- 数字・符号: 4す / 3ね 等

### 3-3 行動語（単独では無害。Target等と組み合わせる）
行く / 会いに行く / 待つ / 待ち伏せ / 出待ち / 乗り込む / 突入 / 集まる / 現地 / 会場 / 下見 / 見に行く / 出入口 / 警備 / 動線

### 3-4 Target語
政治家・候補者・首長・議員 / 学校 / 駅 / 空港 / 市役所・官公庁 / 商業施設 / 宗教施設 / 大規模イベント・フェス・ライブ / 演説会場 / 特定企業

### 3-5 地域細分化
全国 → 都道府県 → 市区町村 → 駅・施設・イベント名。直近の選挙・演説日程・大規模イベント日程（公式発表）と突合。

### 3-6 事件起点
直近の重大事件名 ＋ 模倣 / 次 / 自分も / 称賛。模倣リスクは事件直後72時間を重点。

## 4. プラットフォーム別方針

可否は Claude の現環境での実現性。「間接」は検索エンジン索引経由のみ。

| プラットフォーム | Claudeで可能な範囲 | 検索の工夫 | 限界 |
|---|---|---|---|
| X | 間接（`site:x.com` / `site:twitter.com`、報道・まとめ・警察発表経由） | 変形語＋site指定。ニュース記事内の引用投稿を一次確認 | 投稿全文検索・時系列・過去投稿深掘りは不可。ユーザー提供データ推奨 |
| Instagram | 間接（公開プロフィール/投稿の索引分のみ） | `site:instagram.com` ＋ ハッシュタグ語 | ログイン壁で大半不可。ストーリーズ不可 |
| Facebook | 間接（公開ページ・公開投稿の一部） | `site:facebook.com` ＋ イベント名 | グループ・個人投稿はほぼ不可 |
| TikTok | 間接（動画タイトル・説明文の索引分） | `site:tiktok.com` ＋ 変形語 | 動画内容・音声の確認は不可 |
| YouTube / ニコニコ動画・生放送・チャンネル | 公開動画のタイトル・説明・コメント（取得できる範囲） | `site:youtube.com` / `site:nicovideo.jp` | ライブ配信の即時監視は不可 |
| 5ちゃんねる / 爆サイ / ホスト・地域掲示板 | 公開スレ（索引・アーカイブ経由） | 事件名・地名＋予告語。予告スレは過去ログも確認 | 即時性低。誤情報・釣りが多く確度は原則D〜E |
| はてな / note / ブログ / Yahoo!知恵袋 等 | 公開記事 | 長文の動機表明・遺書様文書・声明文 | 量が多い。文脈で厳格評価 |
| Telegram公開チャンネル / Discord公開サーバー / Reddit / Mastodon・Misskey・Bluesky等 | 公開分のみ、索引範囲で間接 | 日本語圏の過激化コミュニティ名・招待リンク公開分 | 招待制・非公開は対象外 |
| LINE / DM / 非公開グループ / 個人チャット | **対象外** | — | 私的通信。調査しない |
| 公式一次情報 | **最優先で確認** | 警察庁・都道府県警・自治体・鉄道/施設の注意喚起、報道、裁判・逮捕報道 | 発表遅延あり |

## 5. 実行手順（毎日）

1. 到達範囲宣言（上表）。
2. 前回レポートの読込（`threat-monitoring/logs/YYYY-MM-DD.md`）。なければ「初回・差分なし」と明記。
3. 公式・報道の一次情報確認（直近24〜72時間の予告・逮捕・施設の注意喚起・要人日程）。
4. 基本語 → 表記変形 → 行動語 → Target → 地域 → 事件起点の順に、プラットフォーム別に検索（サブエージェントで並列化可）。
5. 発見案件の深掘り: 同一アカウント公開投稿の時系列（可能な範囲）、返信・引用、同一日時/場所/Target への言及。
6. 新規キーワード抽出 → 再検索。新規情報が出なくなるまで拡張。
7. 重複排除 → 前回差分（抽象→具体、不満→復讐、Target→Time→Location→Approach→Preparation）。
8. 評価・出力・ログ保存。

## 6. Pre-Attack Indicator 分類
Intent / Target / Time / Location / Method / Capability / Preparation / Surveillance / Approach / Fixation / Leakage / Escalation / Identification / Mobilization / Copycat / Grievance / Crisis

## 7. 評価基準

- 高: Intent+Target+Time、または Target+Method+Preparation 等、具体要素が複数。
- 中: 強い敵意・復讐・模倣・武器関心・Fixation・Escalation・接近示唆が複数。ただし具体要素不足なら「高」にしない。
- 低: 単発過激発言、一般的政治表現、ニュース反応、転載。

情報確度: A=一次情報 / B=本人公開投稿 / C=信頼できる第三者 / D=転載・スクショ / E=出所不明。
**Claudeは自力で本人投稿を直接確認できない場合が多いので、スクショ・まとめ経由は原則D以下。**

誤検知防止: 政治批判、デモ参加、フィクション、ゲーム、ミーム、ブラックジョーク、歴史議論、ニュースへの反応は単独でThreatとしない。

## 8. 出力形式

### 8-1 案件ごと
`新規/継続/変化あり` ／ 投稿日時 ／ プラットフォーム ／ アカウントURL ／ 投稿URL ／ 引用（最小限）／ 確認事実 ／ 要約 ／ Threat Indicators（各項目、なければ「確認できず」）／ 危険度 ／ 情報確度 ／ 根拠 ／ 日本国内との関連性 ／ 関連投稿 ／ 関連アカウント（具体的行動上の関連のみ）／ 一次情報の有無 ／ 転載経路 ／ 未確認事項 ／ 分析（事実と分離）／ 推奨対応（通報先）

### 8-2 全体構成
1. 到達範囲と未到達範囲
2. 本日の重要案件
3. 新規確認案件
4. 変化が確認された案件（前回→今回）
5. 継続監視案件
6. 【緊急確認推奨】（具体的Target・日時・場所・方法・準備行動・接近・下見・公共施設/演説会場への具体的脅威・複数アカウントで同一脅威）
7. 日次総括（件数: 新規/高中低/確度A/一次確認済み・未確認、新出キーワード・隠語・Target、複数プラットフォーム共通話題）
8. 追加調査事項（次回の重点）

### 8-3 保存
`threat-monitoring/logs/YYYY-MM-DD.md` に保存し、翌日の差分基準とする。

## 9. 検索結果が空のとき
「今回の公開検索では確認できなかった」と書く。「脅威は存在しない」とは書かない。検索範囲を拡張（別表記・別地域・別プラットフォーム・事件起点）してから結論する。
